## 세 가지 경로로 같은 사례에 닿습니다

사례 하나는 **카테고리 · 도구 · 난이도 · 태그** 네 축으로 동시에 분류됩니다.
"무슨 일을 하려는지"로 찾을 때와 "어떤 도구를 쓰는지"로 찾을 때 접근 경로가 다르기 때문입니다.

| 이렇게 생각날 때 | 이리로 |
| --- | --- |
| "메일에서 일정 뽑는 거 어떻게 했더라" | [카테고리](/categories/) → 업무 자동화 |
| "Ask Gemini로 뭘 할 수 있지" | [도구별](/tools/) → Chrome Ask Gemini |
| "그때 그 프롬프트" | 좌측 상단 **검색** (`Ctrl`/`⌘` + `K`) |

## 각 사례 페이지의 구조

모든 유스케이스 페이지는 같은 순서를 따릅니다. 순서가 고정이라 필요한 부분만 건너뛰며 읽을 수 있습니다.

1. **요약 카드** — 카테고리, 사용 도구, 난이도, 소요 시간, 최종 업데이트
2. **어떤 문제를 해결하나** — 이걸 왜 하는지. 여기만 읽고 덮어도 판단이 됩니다
3. **사전 준비** — 계정, 확장, 권한 등 없으면 막히는 것들
4. **단계별 사용법** — 번호가 매겨진 각 단계 + 캡처 이미지
5. **결과 / 주의사항 / 응용** — 실제로 뭐가 달라졌는지, 어디서 틀리는지

## 캡처 이미지 보는 법

단계 안의 캡처는 **클릭하면 원본 해상도로 열립니다.** 화면이 작아 글자가 안 보이면 눌러서 확대하세요.

## 난이도 기준

| 난이도 | 기준 |
| --- | --- |
| 초급 | 설치·설정 없이 UI 조작만으로 따라 할 수 있다 |
| 중급 | 확장/연동 설정이나 프롬프트 조정이 필요하다 |
| 고급 | API, 스크립트, 자동화 파이프라인이 끼어 있다 |
